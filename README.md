# Peter Jeong

Laboratory scientist turned healthcare data analyst, based in Seattle. Seven years of bench work in clinical and environmental microbiology, including three and a half years in a CLIA-certified public health lab reporting through the Clinisys Apollo LIS. Now I take messy public data, clean it in SQL with every exclusion documented, and turn it into a KPI a manager can act on.

**Tools:** SQL (MySQL), Tableau, Excel, Power BI

## Projects

| Project | Question | Headline | Links |
|---|---|---|---|
| **Seattle Building Permit Cycle Time** | Where does Seattle's permit process stall? | Plan review drives 91% of the slow tail; New construction is 18% of building permits but 67% of the slow ones, stuck in correction loops. | [Repo](https://github.com/jeongwspeter/seattle-permit-cycle-time) · [Dashboard](https://public.tableau.com/app/profile/peter.jeong7168/viz/SeattleBuildingPermitProject/SeattlePermits) |
| **NYC Vendor Rationalization** | How much could NYC save by consolidating its long tail of suppliers? | 797 vendors (4.3%) hold 80% of $31.0B in spend; consolidating tail spend in 23 categories is worth ~$149M a year. | [Repo](https://github.com/jeongwspeter/nyc-vendor-rationalization) · [Dashboard](https://public.tableau.com/views/NYCVendorRationalization/Dashboard1) |

**Next:** a healthcare dataset project (in progress). The Seattle analysis measures median and p90 turnaround, which stage holds the slow cases, and how many correction rounds they go through. That's the same structure as specimen turnaround time.

Both projects use real public data (Seattle Open Data, NYC Checkbook), not synthetic sets. Each repo has the SQL in run order, the result of every query, and a cleaning decisions log.
